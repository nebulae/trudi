# TRUDI record_finding / export gates — full reference

The authoritative, server-enforced gate list. CLAUDE.md carries the operating summary; this file is the detail. Gates are enforced in code (`tools/_gates/`), not by this prose.

**Server-enforced. `record_finding` refusals return `{success: false, gate: "<id>", ...}` with a remediation message. The broad `gate` value is stable; when present, `detail_gate` names the specific checker that fired. `reason.pre_report_check` returns structured `blocking_issues` that must be resolved before `export_execution_log`.**

| Gate | Applies to | Condition | Remediation |
|------|------|-----------|-------------|
| `mcp_routing` | `record_finding` | `linked_call_id` → `source="claude_code_bash"` entry executing a forensic binary | Re-run via the named MCP wrapper; use that `_trudi_call_id` |
| `dair_required` | `record_finding` | No `dair_assess` in last 30 trace entries | Call `dair_assess` first |
| `lineage_required` | `record_finding`, `record_self_correction`, `dair_assess`, `reason.*` | `input_call_ids` empty after genesis grace (first 5 entries) — or contains unknown/fabricated cid | Pass `input_call_ids=[<cid>, ...]` from upstream entries |
| `confirmed_requires_linked_call_id` | `record_finding` | Tier=CONFIRMED and `linked_call_id == 0` | Pass `linked_call_id=<_trudi_call_id>` from source tool result |
| `linked_call_id_must_exist` | `record_finding` | `linked_call_id` not in trace | Use real `_trudi_call_id` |
| `mitre_technique_validation` | `record_finding` | Description contains unknown ATT&CK ID | Fix T-ID (`correlate.mitre_validate`) or remove |
| `tier_contract` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} and the artifact classes of the cited calls (`input_call_ids` + `linked_call_id` + `transfer_call_ids` + `session_binding_call_ids`) reach a LOWER tier for the claim's `act`/`channel` (`data/fk/tiering.yaml`) | Run the tools named in `tier_path`, cite them, re-record — or record at `tier_achievable` |
| `confirmed_requires_supported_evaluate` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} and no `reason.evaluate_finding` for THIS claim (matched by claim key + entities, then description) returned SUPPORTED — or the matched evaluate's declared claim differs (`claim_mismatch`) | Call `reason.evaluate_finding` with the same typed claim until SUPPORTED (a fact-check: the stated facts are in the cited rows), or downgrade to SUSPECTED |
| `confidence_and_citation` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} and no recent `reason.confidence_score` AND `reason.cite_check` referencing this finding's text | Call both with description in each `user_message`; resolve UNCITED_CLAIMS_PRESENT; downgrade if `confidence_score`'s tier is lower |
| `typed_claims` (detail of `evidence_strength`) | `record_finding` | Tier ∈ {CONFIRMED, LIKELY, UNCONFIRMED} AND `claim_kind`/`category`/`act` not all declared, or a conditional field is missing (`act="egress"` ⇒ `channel`; `act` delivery/possession ⇒ `recipients`; `actor_kind="human"` ⇒ `actor`; `act="attribution"` ⇒ `actor_kind` (declare `unknown` honestly rather than leaving it blank to skip the binding gates); a negative in logon_auth/device_initial_access ⇒ `window`) | Declare the typed claim (see **Typed claims** below) — every refusal names the missing field and its enum; gates key on the declared structure, never your wording |
| `typed_disposition` | `misc.record_disposition` | Invalid `target_kind`/`reason` pairing, or an evidence-asserting reason (`excluded`/`ruled_out`/`refuted`/`not_a_principal`) without `evidence_call_ids` naming successful evidence tool calls | Fix the enum / cite the evidence calls |
| `challenge_sticky` (detail of `evidence_strength`) | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} AND the most recent `reason.evaluate_finding` for this finding returned CHALLENGED/UNCERTAIN — or a later SUPPORTED was obtained with no evidence tool call between it and the challenge | Run the discriminators the reviewer asked for (new evidence tool calls), re-evaluate to SUPPORTED, or downgrade to SUSPECTED |
| `refusal_rewording` | `record_finding` | The finding matches a recent evidence-demanding refusal (same claim key `kind|category|act` + overlapping entities/principal/recipients, or the same `tested_hypothesis_id`) AND no evidence tool call has run since | Run the tools the refusal named, cite new evidence (`input_call_ids`), or downgrade to SUSPECTED — rewording is not remediation |
| `max_pass_cap` | `record_self_correction(trigger="dair_max_pass_cap")` | The latest `dair_assess` carries a `verified: null` challenge whose `challenge_method` has not run | Run each open `challenge_method`, or `misc.record_disposition(target_kind="tool", target_id="<method>", reason="inapplicable"\|"absent_from_evidence")`, then `dair_assess` again; `pre_report_check` also blocks on never-run challenges |
| `hypothesize_required` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} AND (`category` ≠ `other` OR `act` ∈ execution/persistence_install/account_creation/egress/c2/lateral_movement/credential_access) AND no recent `reason.hypothesize` AND no `tested_hypothesis_id` | Call `reason.hypothesize`; pass returned `hypothesis_id` as `tested_hypothesis_id` |
| `principal_attribution_grounding` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} AND `principal=` declared with `actor_kind="human"` AND `session_binding_call_ids` do not name a session-artifact call (or a logon-enumeration command) | Pull the logon-session/source artifact (`ez.evtxecmd` / `misc.evtx_filter` 4624/4625/4778/4779 by type+source) and pass its cid in `session_binding_call_ids`, or downgrade to SUSPECTED |
| `named_actor_attribution_grounding` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} AND `actor_kind="human"` with no `principal` AND `act` ∈ core acts (egress/delivery/possession/execution/account_creation/persistence_install/destruction/lateral_movement/credential_access/c2) AND no session binding | Same remedy — `session_binding_call_ids` placing the person at the host during the act, or downgrade to SUSPECTED |
| `interactive_injection_grounding` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} AND `session_type="interactive"` AND `act` ∈ {account_creation, persistence_install} AND removable media is in evidence AND **either** no complete `misc.device_install_inventory` covers `window` **or** the inventory **flagged** a keystroke-injector with no typed rule-out | Run **`misc.device_install_inventory`** over `setupapi.dev.log` covering the window; a flagged injector is ruled out only by `rule_outs=[{"what":"injector","call_ids":[...]}]` or a device disposition (`ruled_out`, with evidence + window); else downgrade to SUSPECTED |
| `exfil_channel_grounding` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} AND `act="egress"` AND `transfer_call_ids` do not name evidence calls carrying a transfer artifact | Cite the TRANSFER artifact call (FTP/transfer log, bytes sent/written, USN `$J` write/rename, removable-volume LNK/`MountedDevices`, mail attachment, SRUM/netflow) in `transfer_call_ids`; else downgrade to SUSPECTED |
| `offhost_delivery_grounding` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} AND `act` ∈ {delivery, possession} AND `receipt_call_ids` do not name a destination-side receipt (HTTP 2xx, FTP 226, SMTP 250/DSN, server/access log) | Cite the receipt call in `receipt_call_ids`, re-scope to `act="egress"`, or downgrade |
| `attribution_required` | `record_finding` | Tier ∈ {CONFIRMED, LIKELY} AND `threat_actor=` declared (or a G-/APT-/FIN-id appears in the prose without being declared) AND no recent `attribution.attribute_actors` call | Declare `threat_actor` and call `attribution.attribute_actors` first |
| `pre_report_check_required` | `export_execution_log`, `write_final_report` | The most recent `reason.pre_report_check` entry has `ready_to_report` ≠ true (or predates the typed flag) | Call `reason.pre_report_check()`; resolve `blocking_issues` first |
| `pre_report_check_required` / structural blocking issue | `reason.pre_report_check` → `export_execution_log` | A contested principal at MEDIUM+ likelihood, a `distinct_principal` hypothesis, or a forced principal `candidate_pivots` entry was never dispositioned — no CONFIRMED/LIKELY finding binds it (`principal` + `session_binding_call_ids`) and no typed principal/hypothesis disposition settles it | Establish the controller (run the discriminators), or `misc.record_disposition(target_kind="principal"\|"hypothesis", ...)` with `excluded`/`refuted`/`not_a_principal`/`same_as` (+ evidence) or `controller_unknown`/`evidence_unavailable` (parked; `evidence_unavailable` downgrades to a report-caveat warning when a `source` disposition records the logon sources absent) for every mandatory principal before Report |
| `negative_completeness` | `record_finding` | Tier=UNCONFIRMED AND `claim_kind="negative"` in `category` logon_auth/identity/persistence/exfil/device_initial_access AND the trace did NOT search every source in the category manifest (e.g. a "no RDP/logon" claim that never parsed the **TerminalServices** channels, not just `Security.evtx`), OR a searched log's `coverage_window` does not span the declared `window` (a log silent about the window cannot ground a negative) | Search the missing sources (the refusal lists their ids; the TerminalServices channels live in the full `winevt\Logs\` on the mounted image, not the CyLR/triage set; for out-of-coverage windows pivot to VSS / carved EVTX), or — only for a source genuinely not in evidence — `misc.record_disposition(target_kind="source", target_id="<source id>", reason="absent_from_evidence")` |

**Anti-reuse on `confidence_and_citation`:** one `reason.confidence_score`/`reason.cite_check` cannot satisfy the gate for two findings with the same description. The matched call's `call_id` must exceed the `call_id` of any prior finding entry with that normalized description — every finding gets a fresh check.
